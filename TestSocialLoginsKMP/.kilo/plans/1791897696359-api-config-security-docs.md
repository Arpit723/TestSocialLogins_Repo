# Plan: Document Google/Firebase Config Security Posture

## Decision (confirmed with user)
**Keep + document.** `google-services.json`, `GoogleService-Info.plist`, and the `Info.plist` URL scheme stay committed to git. These are public identifiers (Firebase's official stance), not secrets — they ship inside the APK/IPA regardless and are protected by Google Cloud Console restrictions (bundle ID + SHA-1), not by hiding them. No code, build, or `.gitignore` changes.

## Current state (verified)
- Android: `shared/src/androidMain/kotlin/com/bk/testsocialloginskmp/auth/AndroidAuthClient.kt:115-123` reads `default_web_client_id` from resources generated by the `googleServices` Gradle plugin from `androidApp/google-services.json`. No hardcoded IDs in Kotlin.
- iOS: `iosApp/iosApp/GoogleSignInBridge.swift:8` reads the client ID from `FirebaseApp.app()?.options` (populated by `FirebaseApp.configure()` from `GoogleService-Info.plist`). No hardcoded IDs in Swift.
- Values present in repo: OAuth Client IDs (iOS, Android, Web), 2 Firebase API keys (`AIzaSy…`), `GOOGLE_APP_ID`, GCM sender ID, plus `androidApp/debug.keystore` with standard passwords.
- No CI workflows exist. Git working tree is clean; all config files are already tracked.
